# 橙子音乐 · iOS 测试版

测试版是**本地运行的正式版镜像**：直接服务 `ios/www`（正式版构建产物），服务脚本与云端部署完全同构（`www/server.js`：静态站点 + `/api/*` 音源接口）。

## 启动

- 双击 `启动测试版.cmd`，或
- 命令行：`node test/start.mjs`（默认端口 3000，可用 `PORT=3001` 换端口）

访问：

- 电脑浏览器：`http://localhost:3000`（构建产物写死 iOS 界面，电脑上也能完整测试 iOS UI）
- 手机（同一 Wi-Fi）：`http://<本机IP>:3000`
- 本地测试环境自动以「本地测试」账号登录，数据只存本机，不碰云端账号。

## 测试注意

- 改代码后重新构建（`node tools/build_web.js --out www --platform ios`），**刷新页面即可生效**，无需重启服务（服务实时读 www 目录）。
- 偶发页面异常时强刷（或清 Service Worker）再看。

## iPhone 机型模拟器（看真机效果）

在桌面浏览器里预览 **standalone 全屏 + 灵动岛 / 刘海安全区** 下的实际布局，不用抱手机也能确认顶部间距：

- 电脑：`http://localhost:3000/__iphone`
- 手机 / 局域网：`http://<本机IP>:3000/__iphone`

iframe 里跑的是**同一份测试版页面**（可直接点击切页、打开播放页和弹层），外层画机身、灵动岛、状态栏、Home 指示条；服务端会把该机型的 `safe-area-inset-top/bottom` 作为同源外部样式表注入，所以看到的是真机 PWA 排版，而不是桌面浏览器的近似值。

### 上下滑只作用于橙子音乐内部

- **自动**（默认）：落在播放页 `#nowPlaying` / 底部 dock `#tabbar` → 派发真实 `TouchEvent`，触发应用自己的 `next(±1)` 切歌（上滑下一首、下滑上一首，阈值 46px）；落在列表 / 内容区 → 滚动翻页（带惯性）。
- 可强制「翻页」或「切歌」模式。拖拽结束会拦住浏览器补发的 click，避免误点歌 / 误进歌词页。
- 「模拟上滑 ↑ / 模拟下滑 ↓」一键演示；「显示触点」显示手指位置与手势 HUD。
- 系统级手势（控制中心、回主屏）不在模拟范围内。

- 开关：安全区标线（红=顶部、蓝=底部，直观确认内容没被遮挡）、状态栏与灵动岛、Home 指示条
- 缩放：默认自动适应窗口（布局变化会自动重算），可切 100% / 75% / 50%；「强制刷新」绕 Service Worker 缓存
- 切换机型**不会重载页面**，当前浏览位置与播放状态保留
- 链接参数：`?d=18pm` 指定机型、`?m=page|song|auto` 指定手势模式、`?s=0.75` 指定缩放
- 机型与缩放都用固定按钮组，**页面内没有原生 `<select>`** —— 原生下拉的展开层由浏览器独立渲染，在预览面板里会漂移成黑块

> 仅在本机 / 局域网 host 生效；模拟器页面在 `ios/test/` 下，不进 `www`、不会随正式版部署。改过 `ios/server.js` 后需重新构建并重启测试服务。

## iOS 端更新工作流（2026-11-15 起生效）

1. **改代码**（`ios/shared/...`）。
2. **本地测试版更新测试**：构建到 `ios/www`，经 `ios/test` 入口启动本地服务验证（本目录）。
3. **用户确认**测试版是否符合要求。
4. **经确认后**迭代版本号 `vX.Y.Z`（只改 iOS 端，与 Windows 版本互相独立），撰写本次更新说明存放 `ios/RELEASE_NOTES/vX.Y.Z.md`（首行 `# vX.Y.Z（YYYY-MM-DD）`）。
5. **更新说明与版本号再次确认**后：
   - 推送更新说明到云端 —— 云端（`release-notes.json`）只保留**最近 3 次**更新说明（构建时按版本倒序截取，多出的最旧版本不进产物；`ios/RELEASE_NOTES/` 目录历史文件留档不删）；
   - 并把最新代码推送到云端，更新正式版软件。
6. **正式版落地后**，测试版即与云端正式版同步（同一份 `ios/www`），作为下次测试的基线。
